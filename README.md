## 小程序输入对照（0.12.12-preview，诊断预发布）

新录像仍出现执行提示后约 1.8 秒广告才关闭，0.12.11 尚未解决故障手机的等待。新增可恢复的输入对照，入口：智能跳过 → 设置 → 无障碍方式 → 输入对照。保留原 Root / Shizuku 两种方式与设置三行。

保持 Shizuku 方式，先选“无障碍手势（保留前台识别）”复测：只替换坐标输入，保留增强任务监听。也可分别对照 GKD 固定命令与虚拟触屏；选“当前兼容输入（默认）”恢复，默认不会自动改变。显式节点点击和第三方规则的 800ms 延迟保持。记录区分实际输入分支，接口受理仍不等于广告关闭。具体证据和限制见 [对照说明](docs/wechat-input-comparison-0.12.12.md)。

## 小程序额外等待（0.12.11-preview，本地测试）

对齐 GKD 的同步成功后继续检查其他规则逻辑；每次继续前重新读取当前页面，不沿用旧节点。保留规则原有延迟与冷却，保持已验证的 InputManager 输入方式。隔离测试中五轮连续规则的第二步间隔为 15～17ms；不能代替故障手机微信实际效果。详细证据与输入参数对照见 [调查说明](docs/wechat-delay-0.12.11.md)。

## 延迟触发与 Shizuku 增强（0.12.10-preview，本地测试）

按 GKD 的执行时序保留延迟匹配计时，延迟到期重读当前整页；连续局部刷新不再推迟整页补检。支持已授权 Shizuku 的默认屏幕前台任务监听和坐标输入。使用方式：智能跳过 → 设置 → 无障碍方式选择 Shizuku，确认服务行显示“Shizuku 增强已连接”；GKD 与 NoAdMi 需要分别授权。无连接时保留无障碍后备，并显示状态。

微信故障手机仍待实际验收；执行记录与提示代表动作接口受理，不等同于广告已关闭。本轮未发布 GitHub。

## 智能跳过场景与提示（0.12.9-preview，本地测试）

应用规则的搜索框、排序 / 展示分组 / 筛选三按钮统一留出间距。同名 Activity 重复进入时，按 GKD 语义建立新场景，更新匹配时间和对应次数 / 延迟；普通内容事件不重置规则。

设置新增“跳过提示”：右侧开关默认关闭，点击标题编辑文字，留空恢复“已发送跳过操作”。提示仅在实际动作成功回调后出现，使用不接收触摸、不中断焦点的服务自身无障碍提示层，关闭、锁屏和服务退出会清理。新执行记录显示节点点击或坐标手势的实际分支；调用被受理不等同于页面已经关闭。

故障微信手机暂未连接，真实场景仍需安装测试包复测，不能把隔离页通过标为微信已修复。与 GKD 的状态 / 输入差异见 [调查说明](docs/wechat-miniapp-investigation.md)。

## 订阅编辑与 JSON5 查看（0.12.8-preview）

“详情与规则”内每个订阅只保留编辑订阅、规则分类、应用规则、全局规则四个操作。编辑订阅弹窗右上角依次为复制、更新，正文显示链接与查看订阅 JSON5，左下角删除，右下角取消 / 保存。删除必须再次确认。更新使用当前输入链接，校验成功才同时保存来源与规则；保存仅修改链接。本地订阅提供查看和编辑 JSON5，隐藏远程专用操作。链接与 JSON5 入口、两个本地 JSON5 入口之间使用统一间距和相同圆角样式。

## 订阅与应用规则管理（0.12.7-preview）

应用列表改为后台读取、后台搜索排序和原生列表复用，避免一次创建所有应用控件。提供按名称、最近使用、最近触发排序；系统应用、用户应用、未安装应用分别勾选展示，支持只看当前订阅白名单（应用规则开关关闭）。展示筛选不会更改规则开关，搜索与滚动位置在返回时保留。

“详情与规则”新增规则分类开关；单独设置的规则组优先于分类，分类只作用于应用规则。订阅更新保留分类和其他开关。远程订阅链接可复制、编辑；仅接受 HTTPS，保存链接不替换现有规则，更新仍校验订阅 ID。

最近使用来自本次升级后、启用智能跳过时实际确认的前台应用切换，仅记录包名与时间；未记录的应用按名称排列。最近触发来自该订阅最多 200 条执行记录中的成功动作，清空记录会清除这部分排序依据。未额外申请使用情况权限。

## 智能跳过执行器（沿用 0.12.6-preview）

运行适配参考 GKD 1.12.1 / 92：事件节点优先，按需读取窗口根节点，先匹配目标再检查排除条件；应用或动作变化后的 3 秒内每 300ms 补检，并继续遵守规则的强制检查、延迟、冷却和次数限制。Android 原生节点调用采用有界等待，迟到结果释放；本机诊断只保存原因与计数。原生点击优先、失败再转中心手势，`clickCenter` 使用中心坐标。在设置中选择并授权 Shizuku 后，增强通道增加默认屏幕前台任务监听，坐标输入优先使用 InputManager，接口不可用时保留固定 input 命令后备；未接通时使用无障碍手势，服务行显示连接状态。Root 方式仍使用原无障碍输入。

本版未增加拍机堂专用规则或修改原订阅。第二台手机复测结果与逐项边界见验证记录；画面停留和复杂页面读取性能仍需继续观察。

订阅开关按 ID 保持控件稳定，保存独立于下载任务；快速切换以最后一次选择为准，不再因整组刷新闪烁或保存时禁用而无法点击。

智能跳过直接显示“启用”和默认折叠的“订阅管理、设置、执行记录”。自动更新与移动网络更新位于订阅管理；设置保留无障碍服务、无障碍方式和跳过提示，服务开关直接操作，不跳转。有开关的项目集中在上方，下方只保留一个“详情与规则”入口，进入后按订阅用独立卡片展示信息，点击卡片原地展开或收起详情；“添加订阅链接、导入本地规则、立即更新订阅”始终排在最下方；订阅弹窗与主页使用一致的颜色、圆角、文字和间距。支持 Root / Shizuku 控制，许可统一放在整体“关于”；App 广告按应用折叠，测试版本说明等标题统一垂直居中。

新增 **广告管理 → 智能跳过**，与官方广告设置、App 广告并列。支持 GKD 格式的订阅、本地导入编辑、应用与规则组开关、无障碍执行及本机执行记录。使用和构建见 [智能跳过](SMART_SKIP.md)，来源与许可见 [第三方说明](THIRD_PARTY_NOTICES.md)。默认不附带第三方订阅；原有 Hook 设置保留。

规则线索参考 [HyperCeiler 应用商店 DisableAds](https://github.com/ReChronoRain/HyperCeiler/blob/5af3daeff128130afe10c1aa1d1534d425ec2f71/library/libhook/src/main/java/com/sevtinge/hyperceiler/libhook/rules/getapps/DisableAds.java)。该版本的 [Browser 入口](https://github.com/ReChronoRain/HyperCeiler/blob/5af3daeff128130afe10c1aa1d1534d425ec2f71/library/libhook/src/main/java/com/sevtinge/hyperceiler/libhook/app/Browser.java) 没有独立去广告规则。本项目依据本机 APK 的实际方法和调用关系独立实现，不整段移植上游规则。

本地试验的应用卸载／停用／恢复功能已从 NoAdMi 删除；对应需求和参考代码单独交接 HyperPriv，不包含在 NoAdMi APK 中。

## 安装与设置

从 0.7.x 或更早版本升级时，请先完成下方“从 NSP 旧版迁移”，再覆盖安装，以保留原有开关。

1. 从 [Releases](https://github.com/tiancaiProgramer/NoAdMi/releases) 下载并安装 APK。
2. 在 LSPosed 中启用 NoAdMi，勾选米家及使用的运动健康版本；现代模块不需要勾选 NoAdMi 自身。Play 版运动健康的包名为 `com.xiaomi.wearable`，与国内版不同；升级模块后需补勾这个作用域。
3. 打开模块，展开分类设置。修改规则后强行停止并重新打开对应目标应用。
4. 关闭“隐藏”开关并重启对应应用，即可恢复原有显示。也可以在 LSPosed 中禁用模块。

使用浏览器和应用商店的新 Hook 时，需在 LSPosed 补勾“浏览器”（`com.android.browser`）和“应用商店”（`com.xiaomi.market`）；升级模块后退出并重新进入作用域可刷新推荐列表。

使用系统 Hook 时，另需勾选“手机管家 / 安全服务”（`com.miui.securitycenter`，网络助手）和“系统服务组件”（`com.miui.securityadd`，游戏助手）。其他官方广告后台开关不需要这些 Hook 作用域，但需要 Root 授权；系统工具广告另外需要“小米账号”作用域。

## 系统应用广告

“广告管理 → 官方广告设置”展开后，顶部立即显示读取提示、进度圈和当前应用，随后读取原应用实际状态，可单项切换或“一键关闭官方广告”。可修改系统工具广告、系统个性化广告推荐、天气内容推广与视频卡片、垃圾清理推荐内容、应用商店个性化服务、浏览器个性化内容与广告推荐、下载管理资源与热榜推荐、日历内容推广。打开表示广告或推荐已启用，关闭后会回读核对；读取或保存失败的项目显示原因，单独计入未处理。

需要用户给予 NoAdMi Root 授权，当前支持机主用户空间。本地配置保存前会停止对应应用，后续启动读取新设置；不清除应用数据。全部可写项在后台完成，界面停留于 NoAdMi。系统工具广告需要另在 LSPosed 勾选“小米账号”（`com.xiaomi.account`），重启账号应用后由其自身进程执行原有官方保存逻辑。成功需同时确认服务结果及状态回读，不读取或导出账号凭证。当前后台桥接需要 Android 14 或更高版本；0.9.3 在 Android 16、账号 R-25.10.23.03 上实测开启与批量关闭均成功。

文件管理的“扩展服务”同时包含云盘等普通功能，不纳入批量关广告；当前实现未适配手机管家的独立官方广告开关。其他可后台操作的项目不显示原生设置页链接。小米账号作用域、系统版本或接口不支持时，“系统工具广告”只显示“打开官方设置”入口，不显示后方开关；仅在手动点击该入口时跳转。个性化广告推荐关闭后不等于减少广告数量。各机型、地区和应用版本的设置与广告位可能不同；无法识别时保留原状态。

成功保存提示在 3 秒内最多显示一次，每次设置仍立即保存；失败提示正常显示。
网络助手规则仅隐藏已核对的四个具名入口，保留流量统计、套餐设置、联网管理、流量排行。若服务端改变推广文案或控件结构，未知项保持原状。充值入口也可能提供用户需要的服务，按需选择。

游戏助手规则针对当前系统服务组件的游戏盒子主页：使用该页面专用的 H5 布局参数收起热玩排行、游戏盒子和大卡片推广，不修改 Android 系统地区、原生账号、GPU 或隐私状态；空游戏列表的游戏中心推广另按页面结构收起。保留添加游戏、游戏记录和设置。新人弹窗只拦截其专用展示条件，手动发起的加速隐私同意与购买流程不在该规则内。旧版原生游戏助手、游戏中的全部侧栏与已添加游戏业务尚未完整验证。

历史系统 Hook 验证设备为 MIX Fold 3 / HyperOS `OS3.0.304.0.WMVCNXM`，安全服务 `12.6.8-260609.0.1`、系统服务组件 `9.12.05-260130.0.1`、天气 `17.0.3.34-HD`。这些是测试记录，不是版本限制。

“框架服务已连接”表示模块已收到框架服务并完成远程设置初始化，目标应用的实际命中可通过 LSPosed 日志或 `adb logcat -s MiClean` 核对。

“关于”内可设置“显示桌面图标”。关闭后，可从 LSPosed 的模块设置重新打开 NoAdMi。该开关只调整桌面启动别名，不禁用设置页和 Hook；桌面可能稍后刷新。

## Play 版中国大陆兼容（实验）

“程序管理”内的米家、小米运动健康各直接显示一个兼容开关，默认关闭。开启后重启目标应用，再由用户选择中国大陆。米家跳过分包下载检查与提示；运动健康放行中国大陆选择，并跳过启动及引导结束时的大陆版迁移跳转。

兼容开关不自动更改地区、账号或隐私同意状态，也不迁移、删除健康或设备数据。原地区切换流程可能要求重新登录，切换前请先确认所选地区。实机已确认两款应用进入中国大陆主页；用户确认米家设备列表和运动健康刷新同步正常。尚未遍历所有设备和业务，不承诺 Play 包具有大陆版的全部功能。关闭兼容开关不会自动恢复此前选择的地区。

从 versionCode 19 起，Play 版运动健康也加载去广告、运动页与“我的”入口规则，两种运动健康共用这些选项，地区兼容仍由独立开关控制。Play 版米家使用单独核对的方法和 13 个菜单资源映射，支持广告、底栏与“我的”入口规则。

选项仅隐藏宿主已有内容。Play 版可能使用海外页面布局；“活力竞赛”开关同时覆盖已核对的大陆与海外布局，不改变地区或 Play 渠道。测试的 Play 内置脚本没有“我的资产”入口，“我的资产”开关不会改为删除“奖品”。原生已隐藏或不存在的入口保持原状。

## 升级与边界

- 包名沿用 `io.github.miclean.module`，以保留作用域。旧版先准备设置迁移，再使用相同签名覆盖安装；不要卸载或清除数据。
- 从旧版分类总开关迁移时，保留原本实际生效的隐藏状态，避免此前未生效的选项突然隐藏入口。
- 米家底栏至少保留一个入口；全选隐藏时保留原底栏。关闭模块的“隐藏商城”后，米家原生设置仍可能使商城不显示。
- 动态页面需要匹配结构指纹；App 内部脚本或方法变化可能导致部分规则跳过。未知组件原样放行，不承诺所有版本的全部选项均生效。
- 原有 Hook 仅处理列出的入口和广告位，不全局拦截网络请求或弹窗，不覆盖所有设备插件的广告。

## 从 NSP 旧版迁移

0.8.0 改用 libxposed 的框架 Remote Preferences，移除了 `xposedsharedprefs`、`MODE_WORLD_READABLE` 和旧 Xposed Hook 依赖。仅删除旧声明不能保证设置正常读取，因此本版同时更换设置传输与 Hook 入口。

旧版 NSP 设置位于框架私有目录，现代 API 不提供直接读取旧文件的能力。请先用下列工具在已授权 Root 的手机上备份并准备迁移，再覆盖安装；如果已升级但旧目录尚在，也可以准备迁移后重开模块。不需要卸载或清除数据。

```sh
python3 tools/stage_legacy_settings.py --adb /path/to/adb --serial DEVICE_SERIAL --backup-dir /private/path/noadmi-backup
```

备份目录应在源码树外。工具只读取本模块旧设置，将副本放入模块私有目录；原始文件保留。打开新版后导入远程设置并保留折叠状态。目标进程在远程设置未初始化时跳过所有规则。已完成迁移的远程设置不会被旧本地副本自动覆盖；再次显式准备迁移则使用所准备的副本。

## 编译

先按 [智能跳过构建说明](SMART_SKIP.md) 准备 Kotlin 2.4.21 / D8 9.5.28。需要 Python 3、JDK 17、Android SDK Platform 35、Build Tools 36.0.0，以及 Maven Central 上 `io.github.libxposed` 的 `api`、`service`、`interface` 102.0.0 AAR。分别解压到一个依赖目录中的 `api/`、`service/`、`interface/`，其中均应有 `classes.jar`。

```sh
python3 build.py \
  --sdk "$ANDROID_HOME" \
  --java-home "$JAVA_HOME" \
  --libxposed-dir /path/to/libxposed-102 \
  --kotlin-compiler-dir /path/to/smart-skip-toolchain \
  --d8-jar /path/to/smart-skip-toolchain/r8-9.5.28.jar \
  --work-dir build \
  --keystore /private/path/NoAdMi-original.p12 \
  --store-pass-file /private/path/password.txt \
  --key-alias miclean-preview \
  --output NoAdMi-0.12.11-preview.apk
```

API 仅用于编译，不打包框架实现。APK 包含官方 `service` / `interface` Binder 客户端；见 THIRD_PARTY_NOTICES.txt。原有外部 JKS / PKCS12 签名参数和 Windows 工具链支持保留。升级必须沿用原密钥，私钥和密码不得放入源码包或 GitHub。
