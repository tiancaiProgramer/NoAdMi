# 微信小程序：重复进入与点击差异

故障录像及截图来自另一台暂未连接的手机；当前 MIX Fold 3 只用于模块与隔离夹具验证，不作为微信实际跳过效果通过的样本。

## 已确认并修正的状态差异

GKD 1.12.1 / 92 对应固定提交的 A11yState.updateTopActivity，会对经过真实 Activity 验证的状态事件建立场景编号。同名 Activity 间隔超过一秒再次出现也产生新场景。activity 重置策略随场景更新匹配起点、次数、延迟和冷却，app 策略保留应用周期限制。NoAdMi 0.12.8 只比较包名和 Activity 名，可能在再次打开时沿用已经过期的窗口或触发次数。

0.12.9 增加场景代次；同名事件一秒内去重，内容事件和普通弹窗不重置规则。事件按 App / 类型 / 类名分组顺序处理，过滤自身内容及提示视图事件，队列有界时优先保留状态事件，避免后续内容或其他窗口盖掉真实 Activity 状态。未修改第三方订阅或增加微信硬编码规则。

## 0.12.10：延迟与补检调度

用户确认故障手机上的 GKD 启用了 Shizuku；NoAdMi 有成功也有失败，不能只凭这点判断根因。

对照同一固定提交的 A11yRuleEngine 与 ResolvedRule，修正两处确定的语义差异：

- actionDelay 首次匹配启动后，不再被局部事件的暂时未匹配清零。等待到截止时间再读当前整页并重新匹配，绝不保存旧目标供稍后直接点击。场景变化、规则重置及成功执行仍按各自策略清除延迟，matchTime、前置规则、冷却和次数限制继续生效。
- 整页补检保持独立的 300ms 截止时间，局部事件提前检查后不能不断把补检推迟。延迟到期优先整页读取，超过启动 / 动作后 3 秒及 forcedTime 后停止无必要的轮询；保留的到期延迟不会造成无限后台轮询。
- 最近执行的前置规则身份按 GKD 语义跨 Activity 保留，不能因切换页面误清理而阻断跨页面规则链。

## Shizuku 运行通道

智能跳过 → 设置 → 无障碍方式选择 Shizuku，并通过官方授权后，现有无障碍服务行显示“Shizuku 增强已连接”。首次授权由用户确认，后台不弹授权窗口。无服务、未授权、超时或接口不支持时保留原无障碍输入，并显示状态。切换 Root 不会自动改用 Shizuku 增强。

运行工作进程与服务开关控制进程分离。仅接受 NoAdMi UID 的固定 IPC，不开放任意命令、文本输入、截图或包管理接口。坐标输入再次核对当前用户、默认屏幕、包名 / Activity / 任务 / 代次、亮屏解锁和屏幕坐标；权限与安装等系统界面不执行。提交后的结果不确定时不立即追加一次点击。

当前测试机曾有两个 Shizuku 主进程，工作进程回连提示找不到令牌。经官方“重新启动”恢复后，增强通道及任务监听连接验证通过。这是本机调试发现，不能推断故障手机存在相同冲突。

## 点击与记录的边界

GKD 默认 click 会先对可点击节点调用 ACTION_CLICK，返回成功则结束；否则走中心坐标点击。中心点击优先尝试 Shizuku 输入，失败再使用无障碍手势。GKD 也按接口返回结果记日志，不校验广告已经消失。

0.12.9 的后备只有无障碍手势，Root / Shizuku 设置在该版本只控制自身无障碍开关。0.12.10 增加独立 Shizuku 运行通道：经官方授权连接后，读取默认屏幕的前台任务及监听任务栈变化，坐标动作优先通过 GKD 同类 InputManager 接口执行，接口不可用时保留固定 input 命令后备，保留节点点击优先；Root 方式仍使用无障碍节点和手势。0.12.9 的新记录显示实际 clickNode / clickCenter 分支和节点接口 / 手势回调。不能将旧记录中的通用 click 推断为具体输入方式，也不在节点返回成功后盲目追加一次坐标点击。

跳过提示默认关闭，位于智能跳过设置；点击标题可修改文案，右侧开关独立控制。默认“已发送跳过操作”，只在实际点击 / 手势成功回调后提示，匹配、延迟等待、取消手势、none 动作不提示。提示不表示已经验证页面关闭。

## 本机输入对照

当前测试机的固定 input 命令曾返回成功但未实际关闭夹具；不能据退出码宣称操作完成。最终 code86 使用 GKD SafeInputManager / InputShellCommand 同类的 IInputManager 接口、触屏指针和默认屏幕，五次 800ms 延迟的坐标执行均实际关闭夹具，并分别留下 InputManager 分支记录。Root 无障碍节点延迟执行也通过五次重复进入。该结论只适用于隔离测试，不等同于故障手机微信验收。

## 尚需复测

需要在故障手机上重新打开小程序，结合本轮的新动作分支和画面结果判断。状态机 / 夹具通过不能替代微信真实场景；当前没有证据把未跳过唯一归因于 Shizuku 或某一控件。实际复测前保留这一问题。
