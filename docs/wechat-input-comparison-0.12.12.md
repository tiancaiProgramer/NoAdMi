## 可恢复的输入比较

入口：智能跳过 → 设置 → 无障碍方式 → 输入对照。Root / Shizuku 的原选择与设置三行保持，使用同一 DialogUi。缺省值不写入、不改变现有输入；明确选择后下次坐标动作生效，取消不修改，选择默认可立即恢复。

| 选项 | 行为与记录 |
|---|---|
| 当前兼容输入（默认） | 原 InputManager 实体触屏参数；API 在 DOWN 前不可用才用原 input -d 0 后备。 |
| GKD 命令输入（对照） | 参考固定提交 UserService / UserServiceWrapper 的 input tap / swipe 命令，日志标注 GKD命令输入。 |
| GKD 虚拟触屏（对照） | 参考 InputShellCommand 的虚拟触屏设备 0，日志标注 GKD虚拟触屏，不静默回到默认特权分支。 |
| 无障碍手势（保留前台识别） | 保持 Shizuku 的任务栈与前台元数据，仅用无障碍手势发送坐标；日志标注 手势对照。 |

先保持 Shizuku 方式并比较最后一项，能将前台识别与点击发送分开观察。Root 方式本来就使用无障碍输入；切换整个 Root 方式会同时失去 Shizuku 前台识别，因此不是相同对照。显式 clickNode 与默认 click 的原生成功分支不受此选择影响。

## 参考与保护

参考固定 GKD 提交 5a00f844989471458e4cf4601acb3f4710438f9a，GPL-3.0-only，第三方来源和许可保留。使用本地已有的对应源码核对 UserServiceWrapper.tap、UserService.execCommand 与 InputShellCommand，不声称 NoAdMi 是完整 GKD 应用。

命令仅从已校验的有限非负浮点坐标和 0～60000ms 时长生成固定 tap / swipe；不接受规则命令文本、不暴露通用 shell Binder 接口。沿用调用 UID、当前用户、默认屏幕、前台包名 / Activity / 任务代次、亮屏解锁与坐标范围检查。接口开始发送后结果不确定时不自动再发另一种点击。手势模式仍遵守服务原有前台与代次校验。

输入日志补充实际特权分支及调用耗时；这段耗时只覆盖输入调用，不包括节点发现、规则延迟或页面关闭。执行提示与日志仍表示接口接受，不冒充页面效果确认。
